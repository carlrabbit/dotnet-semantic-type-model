# Coordinated TestData Generation Specification

## Status

Authoritative behavioral specification for M0084 coordinated TestData generation.

This specification composes with:

- `test-data-generation.md`;
- `test-data-profiles.md`.

The canonical model remains the validity boundary. Coordination is TestData runtime policy.

## Purpose

Allow values generated during one invocation to coordinate with other values in that invocation without adding canonical relationship semantics, persistent generator state, or a general dataset model.

M0084 supports four capabilities:

```text
same-object derived values
sequences
shared values
scoped uniqueness
```

Dependency ordering and invocation-scoped state exist only to support those capabilities.

## Public boundary

Coordination is configured through exact-property TestData Profile rules.

Equivalent consumer shape:

```csharp
TestDataProfile profile = TestDataProfile
    .Create(model, "Customers")
    .For(customer)
        .Property(fullName)
            .From(
                [firstName.Id, lastName.Id],
                ctx => $"{ctx.Get<string>(firstName.Id)} {ctx.Get<string>(lastName.Id)}")
        .Property(customerNumber)
            .Sequence(TestDataValueScope.Batch,
                i => $"CUST-{i + 1:000000}")
        .Property(tenantId)
            .Shared(TestDataValueScope.Batch)
        .Property(email)
            .From(
                [firstName.Id, lastName.Id],
                ctx => CreateEmail(
                    ctx.Get<string>(firstName.Id),
                    ctx.Get<string>(lastName.Id)))
            .Unique(TestDataValueScope.Batch)
        .Done()
    .Build();
```

The exact builder/helper type decomposition is implementation-owned, but the public capability must expose equivalent semantics.

M0084 introduces the public coordination scopes:

```text
Root
Batch
```

No other state scope is supported.

## Eligible rule targets

M0084 coordinated rules apply only to **exact property identity**:

```text
canonical declaring owner TypeId + PropertyId
```

They are not valid as profile defaults, containing-object defaults, or Logical Type defaults.

The target property must resolve to a scalar or enum value.

M0084 does not coordinate whole object, array, dictionary, reference, `Any`, union, intersection, or `Never` values through these rules.

Existing M0083 sampling policy may still apply to those other shapes.

## Generation Session

Every public generation invocation creates one fresh ephemeral Generation Session.

```text
Generate(...)
    = one Batch containing one Root

GenerateMany(..., count)
    = one Batch containing root ordinals 0..count-1
```

A second call starts a new session even when it uses the same model, profile, facade, seed, and root type.

Session state is never retained in the profile/facade/model or shared across concurrent invocations.

### Root scope

Root-scoped state spans the complete semantic value graph generated for one top-level root.

It resets before generation of the next root in the same `GenerateMany` call.

### Batch scope

Batch-scoped state spans all roots generated by the current invocation.

It resets after that `Generate`/`GenerateMany` call completes or fails.

## Deterministic structural visitation

Stateful coordination requires a deterministic encounter order.

The required ordering is:

- `GenerateMany` roots in ascending `RootOrdinal`;
- array and dictionary occurrences in ascending structural ordinal;
- effective object properties in existing deterministic canonical/effective order;
- dependency prerequisites before their dependents;
- among dependency-unrelated properties, preserve the existing effective property order.

Changing declaration/graph structure that changes the visitation order of occurrences governed by the same stateful rule may change sequence/shared-first-occurrence assignment.

M0082/M0083 coordinate-derived Random values for unaffected occurrences remain independent of accidental entropy consumption order.

## Same-object dependency model

A derived-value rule declares all sibling properties that its callback may read.

Dependencies:

- must be scalar or enum properties;
- must be members of the same effective object instance as the derived target;
- may themselves be derived values;
- may be inherited effective properties;
- may be optional or nullable;
- cannot use parent/child paths, collection indexes, another root, or arbitrary object traversal.

To keep exact-property rules valid everywhere the target property can occur, every declared dependency must belong to the target property's declaring object's effective property set. A rule cannot depend on a member that exists only on one particular derived containing type.

Dependency declaration order does not control evaluation order.

The profile validates the resulting graph before successful build/composition.

Self-dependencies and dependency cycles are invalid profile configuration.

### Stable dependency planning

For each effective object type, the generator establishes a stable dependency-respecting property plan.

The plan must preserve ordinary property order among nodes not constrained by dependency edges.

Changing fluent rule-declaration order must not change the resulting dependency semantics.

## Dependency callback context

A derived callback receives a read-only dependency context over the **declared dependencies only**.

The public capability must provide equivalent operations to:

```csharp
bool IsPresent(PropertyId property);
bool IsNull(PropertyId property);
T Get<T>(PropertyId property);
bool TryGet<T>(PropertyId property, out T? value);
int RootOrdinal { get; }
```

Exact method names may follow package conventions.

Rules:

- `IsPresent` is false only when an optional dependency was omitted;
- an explicit `NullTestValue` is present and `IsNull` is true;
- `Get<T>` succeeds only for a present, non-null declared dependency whose scalar/enum representation is compatible with `T`;
- `TryGet<T>` returns false for omitted or explicit-null dependencies;
- attempting to read a dependency not declared by the rule is a coordination error;
- an incompatible requested `T` is a programmer/configuration error, not a value-source fallback.

The context exposes generated semantic scalar/enum values; it does not materialize arbitrary CLR object graphs.

### Optional/null dependencies

Dependency ordering guarantees that a declared dependency has been processed before the derived callback runs.

It does not guarantee that the dependency is present or non-null.

A callback that requires a value must use `Get<T>` and therefore fails if the dependency was legally omitted/null. A callback that wants to handle those states explicitly uses `IsPresent`, `IsNull`, or `TryGet<T>`.

## Derived values

A derived rule is an exact-property **coordinated producer**.

Equivalent shape:

```csharp
.Property(fullName)
    .From(
        [firstName.Id, lastName.Id],
        ctx => ...)
```

The callback is invoked only when the target property itself is present and has not been selected as null by ordinary M0083 presence/null policy.

A derived callback must return a non-null scalar/enum candidate.

Returning null is invalid; profile null behavior is expressed through the existing nullability/null-probability policy.

The returned value is validated through the same canonical candidate-validation path used for other explicit TestData values.

Derived results never bypass scalar/enum representation, format, pattern, numeric/string constraints, custom-constraint fail-closed rules, or use-site constraints.

An invalid derived result fails closed; it does not fall through to weighted/terminology/Random sources.

## Sequences

A sequence rule is an exact-property coordinated producer.

Equivalent shape:

```csharp
.Property(customerNumber)
    .Sequence(
        TestDataValueScope.Batch,
        index => $"CUST-{index + 1:000000}")
```

### Index contract

Sequence index is zero-based.

Each exact-property sequence rule has independent sequence state for its configured scope.

The index advances only when the sequence producer is actually invoked for a present, non-null occurrence and is not shadowed by a higher-precedence programmatic generator.

Optional omissions and ordinary sampled nulls do not consume a sequence index.

A sequence callback must return a non-null scalar/enum candidate.

The candidate is validated against canonical constraints exactly like a derived value.

### Root sequence

A Root sequence starts at index `0` for each top-level root.

Matching occurrences inside nested/repeated object instances in that root consume increasing indexes in deterministic structural visitation order.

### Batch sequence

A Batch sequence starts at index `0` for the invocation and continues across root ordinals.

A separate `GenerateMany` call starts again at index `0`.

## Shared values

A shared rule caches one successfully resolved present/non-null value for its exact property and configured scope.

Equivalent shape:

```csharp
.Property(tenantId)
    .Shared(TestDataValueScope.Batch)
```

On the first eligible occurrence in the scope:

1. run the normal value-source resolution pipeline;
2. validate the resulting semantic value;
3. store that value in the Generation Session.

Later eligible occurrences in the same scope reuse the stored semantic value without invoking upstream value sources again.

### Presence/null interaction

Presence and null sampling happen before shared-value lookup.

Therefore an omitted occurrence remains omitted, a sampled-null occurrence remains null, neither creates nor consumes the shared cached value, and only present non-null occurrences participate in sharing.

`Shared` coordinates the value, not whether the property exists or is null.

### Scope

Root sharing caches independently per root.

Batch sharing caches one value across all roots in the invocation.

## Scoped uniqueness

A uniqueness rule requires present non-null values for one exact property not to repeat within its configured scope.

Equivalent shape:

```csharp
.Property(externalId)
    .Unique(TestDataValueScope.Batch)
```

### Participation

Only present, non-null values participate.

Omitted properties and `NullTestValue` do not occupy the uniqueness set.

### Equality

Uniqueness uses canonical TestData scalar/enum representation equality, not object-reference identity or formatted inspection text.

For Binary this means byte-content equality.

For Json it means equality of the stored TestData scalar representation; M0084 does not add JSON semantic normalization.

### Root uniqueness

The set resets for every top-level root.

### Batch uniqueness

The set spans all roots in the current invocation.

### Retryable sources

When a duplicate came from a retryable declarative source, the generator deterministically attempts alternative legal values using an attempt-specific coordinate.

Retryable sources are exact-property TestData Profile weighted values, Logical-Type TestData Profile weighted values, property terminology candidates, Logical-Type terminology candidates, and built-in Random/boundary generation.

Retries are bounded and deterministic.

If the legal/available source domain is exhausted, generation fails with:

```text
TESTDATA_COORDINATION_UNIQUENESS_EXHAUSTED
```

The implementation may choose the internal retry bound/algorithm while ensuring finite exhaustion is diagnosed and no unbounded loop is possible.

### Non-retryable explicit producers

The following are not automatically reinvoked merely to repair a uniqueness collision:

- programmatic property generator;
- programmatic Logical Type generator;
- derived-value callback;
- sequence callback.

If one of those produces a duplicate under an active uniqueness rule, generation fails closed.

This prevents hidden multiple invocation/side-effect semantics for imperative callbacks and prevents STM from rewriting an explicitly derived or sequenced value.

## Coordinated-rule combinations

M0084 deliberately keeps combination semantics small.

The same exact property may not combine:

```text
Derived + Sequence
Derived + Shared
Sequence + Shared
Shared + Unique
```

These combinations are invalid after profile build/composition.

`Derived + Unique` is supported.

`Sequence + Unique` is supported.

`Shared` may wrap ordinary value-source resolution, including a programmatic generator registered separately on the facade.

`Unique` may constrain ordinary value-source resolution and explicit coordinated producers according to the retry rules above.

Presence/null sampling policies remain orthogonal to all coordinated rules.

Profile composition must revalidate the final overlaid coordination rule set, including conflicts and dependency cycles.

## Source precedence

For a present, non-null scalar/enum property:

```text
programmatic property generator
-> programmatic Logical Type generator
-> exact-property coordinated producer
     (Derived or Sequence)
-> exact-property TestData Profile weighted values
-> Logical-Type TestData Profile weighted values
-> property Semantic Terminology Profile candidates
-> Logical-Type Semantic Terminology Profile candidates
-> built-in generation using Effective Sampling Policy
```

`Shared` and `Unique` are coordination modifiers around the successful resolved value according to their rules above.

Presence/null decisions still occur before this pipeline.

Boundary/BoundaryMixed affect only built-in generation.

## Callback failure behavior

Exceptions from M0084 derived/sequence callbacks do not trigger fallback to lower value sources.

Generation fails and exposes a coordination failure through the existing TestData exception/diagnostic surface.

Descriptive M0084 runtime diagnostic categories are:

```text
TESTDATA_COORDINATION_CALLBACK_FAILED
TESTDATA_COORDINATION_CANDIDATE_INVALID
TESTDATA_COORDINATION_DEPENDENCY_UNAVAILABLE
TESTDATA_COORDINATION_DEPENDENCY_UNDECLARED
TESTDATA_COORDINATION_UNIQUENESS_EXHAUSTED
```

Exact diagnostic message text is not a compatibility contract.

Local profile-builder programmer errors may continue to use ordinary .NET argument/invalid-operation exceptions consistent with the existing TestData Profile API.

## Profile validation

Successful profile build/composition rejects, at minimum:

- coordinated rule on a non-exact scope;
- coordinated rule targeting a non-scalar/non-enum property;
- dependency on an unknown property;
- dependency outside the target declaring object's effective property set;
- dependency on a non-scalar/non-enum property;
- self-dependency;
- dependency cycle;
- contradictory coordinated-rule combination;
- invalid scope value.

Validation is based on the bound canonical model and does not defer structurally knowable errors to generation.

## Determinism

For one aligned suite version, same model/profile/settings/root/count/seed produces the same coordinated semantic graphs.

Stateful coordination is deterministic but intentionally depends on deterministic occurrence visitation order.

Separate generation calls never influence each other.

Concurrent calls through the same facade/profile never share sequence counters, caches, or uniqueness sets.

Existing M0082/M0083 entropy independence remains: coordination state must not turn ordinary unrelated Random values back into mutable-RNG consumption-order behavior.

## Failure atomicity

`GenerateMany` preserves its existing all-or-throw consumer behavior.

If coordinated generation fails after earlier roots were internally produced, the call does not return a partial successful list and no failed-session state survives for a later call.

## Compatibility

M0084 is additive on the 6.1.0 development line.

Existing profiles without coordinated rules preserve M0083 behavior.

Existing no-profile M0082/M0083 deterministic tests remain valid unless a separately planned correctness defect is identified.

`TestDataValueScope`, dependency/sequence callbacks, and coordinated profile rules are public API once introduced.

Generation Session state is explicitly not a persistence or compatibility artifact.

## Non-goals

M0084 does not add canonical relationship semantics, canonical TestData annotations, Logical-Type/default/object-scoped coordinated rules, arbitrary property paths, parent/child dependency traversal, cross-object derived values, cross-root dependency reads, relationship/foreign-key binding, heterogeneous multi-root datasets, application-global or persistent sequence state, caller-named sessions, shared object/collection graphs, structural uniqueness for objects/collections, automatic Logical-Type relationship matching, domain faker providers, invalid/adversarial generation, time-series/workflow/state-machine generation, profile persistence/serialization, or regex synthesis.

A later dataset capability may build explicitly on Generation Session primitives without changing this boundary.

## Required consumer evidence

The existing package-based `samples/programmatic-model-catalog/` remains the consumer-documentation vehicle.

M0084 adds one stable scenario:

```text
coordinated-generation
```

The scenario must visibly demonstrate, without CLR materialization:

- same-object derived values;
- a dependency chain;
- a Batch sequence;
- a Batch shared value;
- Batch scoped uniqueness;
- fixed seed;
- several generated roots;
- semantic-value inspection;
- assertions that verify the coordination contract.

Detailed edge cases remain in focused tests.
